# 飞书接入准备清单

> 目标：让 `D:\test3` 这套程序能把结果写进飞书。
> 分两条路线，**先走 A，够用了再上 B**。两条可以同时开，互不影响。

---

## 0. 先决定要哪种呈现

| 出口 | 需要什么 | 能做什么 | 耗时 |
|---|---|---|---|
| **A. 群自定义机器人** | 一个 Webhook 地址 | 日报卡片、高频问题告警、异常通知 | 5 分钟 |
| **B. 企业自建应用** | App ID + App Secret + 权限 + 发版 | 建文档、写多维表格、应用身份发消息 | 30 分钟 |

**只想知道「客户在问什么」→ 走 A 就够了。**
**想要一张能筛选、能透视的台账 → 必须走 B（多维表格）。**

---

## A. 群自定义机器人（5 分钟，零权限）

### 操作

1. 打开目标飞书群 → 右上角 `...` → **设置**
2. 左侧 **群机器人** → **添加机器人** → 选 **自定义机器人**
3. 起个名字（如「七鱼分析」）→ 下一步
4. **安全设置**：勾 **签名校验**，把密钥复制下来（也可以只勾「自定义关键词」，填 `七鱼`）
5. 复制 **Webhook 地址**（形如 `https://open.feishu.cn/open-apis/bot/v2/hook/xxxxxxxx`）
6. 点完成

### 填到 `.env`

```bash
FEISHU_WEBHOOK=https://open.feishu.cn/open-apis/bot/v2/hook/xxxxxxxx
FEISHU_WEBHOOK_SECRET=你刚才复制的签名密钥
```

### 验证

```bash
python run.py feishu-check --send
```

群里应该收到一张蓝色卡片。

## B. 企业自建应用（30 分钟）

### B1. 建应用

1. 浏览器打开 <https://open.feishu.cn/app>
2. **创建企业自建应用** → 填名称（如「七鱼会话分析」）→ 创建
3. 左侧 **凭证与基础信息** → 复制 **App ID** 和 **App Secret**

```bash
FEISHU_APP_ID=cli_a1b2c3d4e5f6g7h8
FEISHU_APP_SECRET=xxxxxxxxxxxxxxxxxxxxxxxx
```

### B2. 开权限（关键，容易漏）

左侧 **权限管理** → 搜索并勾选下面这些。**只勾你真要用的，多勾审核更慢。**

| 你要的功能 | scope | 权限名称 |
|---|---|---|
| 建文档 / 写文档 | `docx:document` | 查看、评论、编辑和管理新版文档 |
| 只读文档 | `docx:document:readonly` | 查看新版文档 |
| 把文档授权给人 | `drive:drive` | 查看、评论、编辑和管理云空间中所有文件 |
| 写多维表格 | `bitable:app` | 查看、评论、编辑和管理多维表格 |
| 应用身份发群消息 | `im:message:send_as_bot` | 以应用的身份发消息到群 |
| 查群列表（可选） | `im:chat:readonly` | 获取群组信息 |

> **最小可用组合**：
> - 只要文档 → `docx:document` + `drive:drive`
> - 只要多维表格 → `bitable:app`
> - 两个都要 → `docx:document` + `drive:drive` + `bitable:app`

### B3. 发版（不做这步，前面全白费）

左侧 **版本管理与发布** → **创建版本** → 版本号填 `1.0.0` → **可用范围**选「全员」或至少包含你自己
→ 保存 → **申请发布** → 等管理员在 **飞书管理后台 → 应用管理** 里审批通过。

> 权限改了、scope 加了，**必须重新创建版本再发一次**，否则不生效。这是最常见的「明明配了还是 403」。

### B4. 把应用加为文档 / 表格的协作者

**scope 给了 ≠ 有权限。** 应用还得被单独授权到具体的表/文档上。

**多维表格：**
1. 新建一个多维表格（或打开已有的）
2. 看 URL：`https://xxx.feishu.cn/base/LNt1bYxxxxxxxx?table=tblYYYY`
   - `app_token` = `LNt1bYxxxxxxxx`（`/base/` 后面那段）
   - `table_id` = `tblYYYY`（`table=` 后面那段）
3. 表格右上角 `...` → **更多** → **添加文档应用** → 搜索应用名 → 权限选 **可编辑** → 添加

**文档：**
1. 新建一个文档，看 URL：`https://xxx.feishu.cn/docx/AbCdEf123456`
   - `doc_token` = `AbCdEf123456`
2. 文档右上角 `...` → **添加文档应用** → 搜索应用名 → **可编辑**

### B5. 填到 `.env`

```bash
# 多维表格
FEISHU_BITABLE_APP_TOKEN=LNt1bYxxxxxxxx
FEISHU_BITABLE_TABLE_ID=tblYYYY

# 文档（留空则每次自动新建）
FEISHU_DOC_TOKEN=AbCdEf123456

# 自动新建的文档要授权给谁，否则只有应用自己看得见
# 填邮箱 / oc_ 开头的群 id / ou_ 开头的用户 id
FEISHU_DOC_OWNER=you@company.com

# 真正写入（0 = 只打印不写）
FEISHU_DRY_RUN=0
```

### B6. 验证

```bash
python run.py feishu-check
```

四项全 `OK` 才算通。

## C. 三个「我明明配了却报错」的坑

### 坑 1：应用建的文档，人在飞书里搜不到

`POST /docx/v1/documents` 建出来的文档，所有者是**应用**，不是人。不去授权，谁都看不见。

代码已经处理了：`write_report` 建完文档会调 `grant()` 把 `FEISHU_DOC_OWNER` 加成协作者。
没配 `FEISHU_DOC_OWNER` 会打一条 warning，文档建出来但没人看得到。

### 坑 2：scope 加了没重新发版

权限变更只在新版本里生效。改完权限 → **版本管理与发布 → 创建版本 → 申请发布**。

### 坑 3：服务器出口 IP 被挡

如果群机器人开了「IP 白名单」，要把**服务器出口 IP**加进去，不是你本机 IP。

服务器上查出口 IP：

```bash
curl -4 -s https://ifconfig.me
```

另外七鱼那边同理——**七鱼 API 白名单只认 IPv4**，而很多机器默认走 IPv6，会一直报 `14008`。
代码里 `src/http.py` 的 `_force_ipv4()` 已经默认强制 IPv4（`IPV4_ONLY=1`），不用改。

## D. 一张表对照：每个错误码该去点哪里

`python run.py feishu-check` 会直接把下面这些翻译出来。

| 错误码 | 意思 | 去做什么 |
|---|---|---|
| `10003` | app_id 格式不对 | 检查有没有复制到多余空格 |
| `10014` | App Secret 不对 | 「凭证与基础信息」重新复制 |
| `99991661` | 应用凭证错 / 未发布 | 确认版本已审核通过 |
| `99991663` | token 无效 | 应用被停用或密钥被重置，重新发版 |
| `99991672` | 缺权限 | 权限管理勾 scope → **重新发版** |
| `1254005` | app_token 不对 | 从 URL `/base/{app_token}` 取 |
| `1254040` | table_id 不对 | 从 URL `table=` 取 |
| `1254302` | 没有这张表的权限 | 表格 → `...` → 添加文档应用 → 可编辑 |
| `131006` | 文档没授权给应用 | 文档 → `...` → 添加文档应用 → 可编辑 |
| `1770001` | doc_token 不对 | 从 URL `/docx/{doc_token}` 取 |
| `19021` | 机器人签名失败 | `FEISHU_WEBHOOK_SECRET` 和「安全设置」里的不一致 |
| `19022` | 机器人 IP 白名单 | 把服务器出口 IP 加进去 |

## G. 飞书 Aily「自定义智能体」（双向，能反过来问它）

前面 A/B 都是**单向写**：我们往飞书塞数据。
自定义智能体是**双向**：我们把统计结果发过去，它回一段分析，我们再写回文档或群。

> 注意区分两个东西：
> - **Aily 工作流应用**（`/aily/v1/apps/{app_id}/skills/{skill_id}/start`）—— 老的 skill 调用
> - **Aily 自定义智能体**（`/aily/v1/agents/{agent_id}/chats`）—— 新的 agent 对话，本文讲这个
>
> 文档位置：**服务端 API → 飞书 Aily → 自定义智能体**

### G1. 三条前提（缺一条就 403）

| 前提 | 怎么满足 |
|---|---|
| 智能体已开启 **Open API 渠道** | 智能体编辑页 → 右上角「使用渠道」→ 打开 **Open API 渠道** |
| 应用有 `aily:agent_chat:write` / `aily:agent_chat:read` | 开发者后台权限管理勾选 → **重新发版** |
| 调用方与智能体**同租户** | 跨租户调不了，`code=10007` |

### G2. 拿 agent_id

打开智能体编辑页，看地址栏：

```
https://xxx.feishu.cn/ai/custom_agent/agent_4k6wf15ngw7wu/builder/persona
                                      ^^^^^^^^^^^^^^^^^^
```

```bash
FEISHU_AGENT_ID=agent_4k6wf15ngw7wu
```

### G3. 接口清单

| 动作 | 请求 |
|---|---|
| 发起对话（异步） | `POST /open-apis/aily/v1/agents/{agent_id}/chats` |
| 获取对话结果（轮询） | `GET /open-apis/aily/v1/agents/{agent_id}/chats/{agent_chat_id}` |
| 创建会话（多轮） | `POST /open-apis/aily/v1/agents/{agent_id}/sessions` |
| 校验可见性 | `GET /open-apis/aily/v1/agents/{agent_id}/agent_visibility/check?channel_type=web_sdk` |

发起对话的请求体：

```json
{
  "user_message": {
    "content": [{"type": "text", "text": "你的问题"}]
  },
  "session_id": "可选，带上就是多轮",
  "stream": false
}
```

返回 `{"data": {"agent_chat_id": "...", "session_id": "..."}}`。
**异步**——拿到 id 后轮询 `GET chats/{id}`，直到 `status` 进入 `Completed` / `Failed` / `Cancelled`，
回复在 `data.content[]` 里（`type == "text"` 的 `text` 字段）。

频控 **10 次/秒**。

### G4. 错误码

| code | HTTP | 意思 |
|---|---|---|
| `10002` | 404 | chat 不存在 |
| `10006` | 403 | **智能体未开启 OpenAPI 渠道** ← 最常见 |
| `10007` | 403 | 非本租户 / 引用了别人的附件 |
| `10008` | 403 | 租户未开通 OpenAPI 访问 |
| `10009` | 403 | 智能体未开启对应身份类型（tenant / user） |
| `10010` | 403 | 应用身份不在可调用范围 |
| `10011` | 403 | 用户身份不在可见范围 |

### G5. 本项目怎么用

```bash
# 自动拿三层聚合结果组 prompt，问智能体，打印结论
python run.py agent

# 自己问一句
python run.py agent --ask "这周客户最不满的是什么，给三个动作"

# 结论直接写成飞书文档
python run.py agent --doc

# 先看 prompt 长什么样，不真调（FEISHU_DRY_RUN=1 或 --mock）
python run.py agent --mock
```

代码：`src/feishu/agent.py`（`AgentClient.ask()` = 发起 + 轮询，一步拿到回复）。

### G6. 这条链路的实际价值

```
七鱼会话 ──→ 本地抽取聚类（零 API） ──→ 结构化高频问题
                                            │
                                            ├──→ 飞书文档（人看）
                                            └──→ 智能体（让它出判断）
                                                      │
                                                      └──→ 结论回写文档 / 群卡片
```

前面 `extract` / `report` 解决「是什么」，智能体解决「所以呢」。
而且**原始会话不出本机**——只把聚合后的十几条问题发过去，没有明细、没有手机号。
