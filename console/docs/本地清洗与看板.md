# 本地清洗与看板使用说明

## 启动

需要 Python 3.10 或更高版本，无第三方包、无 CDN、无需配置外部凭证。在项目目录运行：

```bash
python run.py serve --open
```

默认监听 `127.0.0.1:8848`，只供本机访问。如果端口占用，CLI 会提示实际选用的端口。

```bash
python run.py serve --port 8850
```

这是没有账号系统的本地工具，不要将它直接暴露在公网。服务检查 Host 和写入请求同源性，但这不等于多用户认证。

## 数据源

- **本地数据**：默认 `data/qiyu.db`，或 `.env` / 环境变量中的 `DB_PATH`。
- **演示数据（模拟）**：本地库同目录的 `dashboard_demo.db`。点击“先看演示数据”或“载入 / 查看独立演示数据”时才创建和整理；重复载入不覆盖已有演示库。
- **旧 mock 库**：`run.py ... --mock` 继续使用原有 `mock.db`。网页的独立演示入口不会改它。
- 浏览器启动不自动拉七鱼、不跑 AI、不推飞书、不裁剪历史数据。网页写操作只有确认导入、重新规则清洗和载入演示。
- 分析页的数据源选择会清空分析筛选；导入入口在演示模式下会明确切到本地数据。
- `.claude/launch.json` 包含正常启动配置 `local-dashboard` 与隔离验证配置 `dashboard-verification`。验证配置使用系统临时目录，不把测试导入写入业务库；二者均接受预览工具分配的 `PORT`。

## 导入流程

1. 点击“导入数据”，先下载 CSV 模板，或选择已有 CSV / XLSX。
2. 点击“预览文件”。解析、字段识别、错误行和脱敏样本在本机完成，此时不打开或写入数据库。
3. 核对会话数、预计有效问答数、跳过行、字段映射和样本原话。
4. 点击“确认导入并清洗”。有效行与抽取结果在同一个事务内写入；处理中发生错误时整体回滚。
5. 到“数据清洗”查看操作记录，再到分析页复核问题簇与问答上下文。

部分行无效时只导入有效行；全部无效时禁止确认。预览最多列出前 30 条错误，使用表格行号定位。
寒暄或纯单号等行可能是可读的有效会话，但抽不出问题，这类会话会被记录为“正文中无有效问题”，不是清洗失败。

### 两种表格

**问答表**：至少有“问题”列，“回答”可以为空；每行是一条独立问答。即使多行共享会话ID且都未回复，也不会被拼成一个长问题。

| 会话ID | 客户ID | 客户名称 | 客户群 | 客服 | 时间 | 问题 | 回答 |
|---|---|---|---|---|---|---|---|
| session-001 | user-001 | 示例客户 | 售前咨询组 | 客服A | 2026-11-07 10:30:00 | 滤芯多久换一次？ | 建议每 6–8 个月更换。 |
| session-002 | user-002 | 示例客户二 | 售后一组 | 客服B |  | 退款什么时候到账？ |  |

**会话正文表**：至少有“会话内容”列，一行是一个会话快照。正文可以包含单元格内换行：

```text
[2026-11-07 10:30:00] 客户：滤芯多久换一次？
[2026-11-07 10:30:20] 客服：建议每 6–8 个月更换一次。
[2026-11-07 10:31:00] 客户：换芯可以自己操作吗？
```

说话人可用“客户 / 访客 / 用户 / 买家”与“客服 / 坐席”。使用真实姓名时，请填写“客服”列以明确接待人。正文格式是启发式识别，真实导出格式不同请先看预览；无法识别时会报错，不把导入成功当作字段已正确理解。若表同时有“会话内容”和“问题”，优先读取会话内容。

### 支持的列名

表头忽略大小写、空白、下划线、横线和中英文括号。下表每项择一即可，其余业务列忽略。

| 字段 | 支持的列名 |
|---|---|
| 会话ID | 会话ID、session_id、sessionId、id |
| 会话正文 | 会话内容、聊天内容、对话内容、sessionContent、content |
| 客户问题 | 问题、客户问题、问题原话、question |
| 客服回复 | 回答、客服回答、客服回复、answer |
| 客户ID | 客户ID、用户ID、customer_id、userId |
| 客户名称 | 客户名称、客户名、客户、用户名称、用户名、customer_name、userName |
| 客户群 | 客户群、客户群名称、客户群/渠道、分流组、分流组名称、fromGroup、group_name |
| 客服 | 客服、接待客服、客服名称、客服姓名、staffName、staff_name |
| 开始 / 提问时间 | 时间、提问时间、会话开始时间、开始时间、startTime、asked_at、start_ts |
| 结束时间 | 会话结束时间、结束时间、endTime、end_ts |

时间支持常见 ISO / 中文日期、秒或毫秒时间戳，以及 Excel 日期序号（有效年份 2000–2100）。无时区的字符串按运行机器本地时区解释。正文自带的消息时间优先；其次使用该行会话开始时间。不用逐条加 30 秒等方式估造提问时间。

时间为空保留为未知，不写成 1970 年或今天。启用日期筛选后未知时间记录不参与该日期范围，选择“全部时间（含未知）”可查看。单个会话的独立问答行未填时间时仍保持未知，不借用同会话其他问答的日期。

### 更新与去重

- 提供会话ID：按该ID更新整个会话快照。重新提取后移除旧的多余消息和问答尾部，更新客户、分组和客服元数据；仍存在的 `(会话ID, 问答序号)` 保留问答ID。
- **不要把同一会话拆成增量文件分别导入**，后一次导入不会自动拼上旧快照。多个数据源使用相同会话ID时也会相互更新，请先统一ID规则。
- 缺少会话ID：用映射字段内容生成稳定ID，相同文件重导不会重复；内容变更会视为新会话，不能当作原会话更新。
- 文件内完全相同的映射行会跳过，即使现实中可能是两次不同咨询；需要区分时请提供不同会话ID。
- 缺少客户ID：生成会话级匿名标识，不将全部匿名会话误当作同一客户。不同会话的同名客户不会仅凭名字合并。
- 同一会话在正文表中重复出现时，以最后一条有效快照为准；问答表中的同会话多行则按顺序保留各条问答。

### 文件限制

- `.csv` / `.xlsx`，不支持旧 `.xls`、加密文件和直接上传七鱼批量导出的 ZIP。
- 单文件最多 8 MB、5,000 个数据行；CSV 支持 UTF-8（含 BOM）与 GB18030，可识别逗号或制表符分隔。
- XLSX 读取第一个工作表（按工作表文件名排序），不拼接多个工作表。请把待导入内容单独另存为一个工作表文件；日期格式依赖单元格值，合并单元格不会自动补值。
- XLSX 总解压大小最多 64 MB，最多 2,000 个 ZIP 项，拒绝异常列坐标；不执行公式或宏。

## 清洗和分析口径

本地“规则清洗”与原有 CLI 的 AI `clean` 是不同能力：

1. 忽略机器人/系统消息；合并相邻客户消息和相邻客服回复。
2. 过滤寒暄、确认、纯地址/单号等非问题内容；保留单条有效问题与未回复问题。
3. 归一化全半角、标点、语气词和数字。归一化文本不是模型改写的标准答案。
4. 先合并完全一致的归一化问句，再用字符 2-gram 和业务词典归并相似说法。词典有 16 类概念，但聚类结果不等于人工标签或准确率；不同产品的宽泛同主题问题仍可能误合。
5. 记录规则版本、输入指纹、处理状态和处理时间。正文或元数据变更后重新处理；零问答会话不会永久挂在“待清洗”。

“重新规则清洗”处理当前数据源保留的所有原始会话，不受分析筛选影响。没有原始正文的既有问答继续保留；有正文但已变成纯寒暄的会话会清掉旧问答。簇编号是本次全库计算结果，可能改变，不适合作为外部长期主键。

### 看板

- 所有分析视图共用日期 / 客户群 / 客服条件。
- 概览四个数字是有效问答、问题簇、咨询客户和未回复问答，**不是原始会话数**。
- “有回复”仅表示抽取内容中存在人工客服回复；不能当作“已解决”。
- 高频次数是该簇内问答条数，份额分母是当前筛选有效问答总数，而不是客户数。
- 每日趋势按提问日期统计并补零；时间未知不画入折线。超过一年的范围只绘制最后 366 天，并提示截断；其他指标仍按完整筛选统计。
- 清洗状态是当前数据源全库状态，与日期/分组筛选无关，界面单独标注。
- 点击排行 / 问题簇 / 客户群 / 客户进入对应明细，明细可继续搜索和选择回复状态。
- 点击问题打开右侧详情：脱敏原话、归一化问法、完整回复与上下文。正文已归档时说明无法追溯，不编造消息。
- 客户页最多展示问答量前 500 位；高频问题页最多前 100 类；问题簇页保留全部类别。

### 界面元素

界面按 SkillHub 的 Ant Design / ProLayout 风格对齐，采用白色顶栏、208px 侧栏、`#1677ff` 操作主色、4px 圆角和系统字体。筛选表单、表格分页、状态 Tag、三步导入 Modal 和详情 Drawer 使用统一的紧凑密度，窄屏下导航与筛选区自动换行。

这是原生 HTML / CSS / JS 实现的相同视觉与交互约定，不是已经安装了 React / antd 组件；运行仍只需要 Python。图表数据使用单色蓝，状态标签同时有图标和文字，避免仅靠颜色区分。

### 导出与隐私

“导出脱敏问答”使用当前分析筛选；在明细页还应用搜索、回复状态、指定客户和问题簇。CSV 带 UTF-8 BOM，供 Excel 打开，并处理以 `= / + / - / @` 或控制字符开头的公式风险。

网页和导出使用同一 `mask_pii()`，覆盖常见手机号、身份证、邮箱、长数字、订单号与详细地址。**这是有限的正则规则，不保证所有写法都能识别**；原始文件与数据库仍含原文，应限制本机权限，分享前人工复核。网页本地流程不会向外发送内容。

## 七鱼接入预留

官方开发者文档：[获取会话记录](https://b.163.com/knowledge/public/WXjbs9n3GC/knowdetail?docId=hFBnNYw5ui&pid=244179&docAnchor=hFBnNYw5ui)。2026-11-07 已核对页面说明，未调用业务接口或验证租户权限。

- 批量 `/openapi/export/session` 的 `start / end` 是毫秒，最大 5 天；签名 Query 的 `time` 是 UTC 秒。
- 创建任务与 `/openapi/export/session/check` 检查下载链接分离，同一企业同一时间只能有一个批量导出任务；返回 `14403` 表示等待。
- `id / startTime / endTime / staffName / userId / userName / fromGroup` 与本地 `raw_session` 元数据契约对应。
- 消息结构有 `from`（1 访客 / 0 客服）、`time`（毫秒）、`mType / msg / status`。`status` 还区分正常与撤回消息，未来消息适配不能不加判断地全部当人工文本。
- 官方同时提供 `/openapi/export/session/one/message` 单会话消息接口；旧代码通过质检导出读取正文，不代表质检是唯一获取路径。本轮保留旧连接器，尚未实施该消息接口或联调。
- 官方会话“解决状态”与“客服是否有回复”是不同字段。本地界面只展示有无回复，不映射成解决状态。

后续只需把真实七鱼数据适配到 `raw_session / raw_message`，即可复用本地抽取、聚类、筛选和看板。本轮不新增自动同步，不改动外部凭证，不发飞书通知。
