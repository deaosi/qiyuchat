## 1. 先分清：两条飞书接入线

七鱼有**两条互相独立**的飞书接入线，用途完全不同，配置入口也不同。接错线是最常见的返工原因。

| | **飞书 IM 消息**（本文档） | 飞书 IM 工单 |
|---|---|---|
| 解决什么 | 客户在飞书群里提问，客服在七鱼答 | 内部跨团队协作，员工在飞书里处理工单 |
| 谁在用 | 外部客户 | 内部 / 外部员工 |
| 七鱼入口 | `在线接入 → 飞书接入 → IM 消息` | `员工管理 → 外部员工管理 → 跨团队协作` |
| 产出 | 在线会话（可质检、可统计） | 工单（可流转、可 SLA） |
| 官方文档 | 开发指南 `oOfLGo8sV6` | 产品手册 `Ue5vHEK9CK` |

> ⚠️ **一个飞书应用只能绑一条线。** 两条线要同时用，就得建两个企业自建应用，名字上区分开（例如「XX客服」和「XX工单」）。

## 2. 前置条件清单

开干之前逐项打勾，缺一项后面都会卡住。

### 2.1 账号与权限

- [ ] **飞书管理员权限账号** ✅（官方要求）
- [ ] **飞书企业状态正常** ✅（官方要求：欠费、被限制的企业无法发布应用）
- [ ] **七鱼企业管理员账号** —— 能同时看到「在线接入」和「扩展与集成」两个菜单 ⚠️
  - 普通客服账号看不到「在线接入」，需要管理员或已授权的子账号

### 2.2 版本与配额

- [ ] **七鱼版本 ≥ 专业版** ✅
  - 官方定价页明确：飞书渠道 `标准版 ×` / `专业版 ✔️` / `旗舰版 ✔️`
  - 渠道接入本身**不额外收费** ✅
- [ ] **飞书侧应用配额** —— 飞书对企业自建应用数量有上限（一般够用），建之前先看一眼已有应用列表 ⚠️

### 2.3 环境准备

- [ ] **一个测试群** —— 先别在真实客户群上试
- [ ] **至少两个飞书账号**：一个客服侧（企业内成员），一个客户侧（外部联系人）⚠️
  - 只有内部账号测不出「外部联系人能不能进线」这个关键路径

### 2.4 需要提前拿到的信息

| 信息 | 从哪拿 |
|---|---|
| App ID | 飞书应用 → 凭证与基础信息 → 应用凭证 |
| App Secret | 同上（默认隐藏，点显示） |
| Encrypt Key | 飞书应用 → 事件与回调 → 加密策略 |
| Verification Token | 同上 |

## 3. 接入六步

> 以下步骤的**顺序不能乱**：先建应用拿到凭证 → 七鱼侧绑定 → 七鱼生成回调地址 → 回填飞书 → 加权限发版 → 七鱼配接入条件。
> 顺序错会导致回调地址拿不到、事件订阅验证失败。

---

### 步骤一：创建飞书企业自建应用

**在哪做**：飞书开发者后台（`open.feishu.cn`）→ 创建应用

**怎么做** ✅

1. 选择 **【创建企业自建应用】**
2. 应用类型选 **【企业自建应用】**
3. 填写应用名称、描述、图标

**命名建议** ⚠️

这个机器人会**出现在客户的群里**，客户能直接看到名字和头像。建议：

- 名字用客户能看懂的业务名，例如「XX官方客服」「XX售后助手」
- 不要用「七鱼」「测试」「QA」这类内部词
- 头像用品牌 logo，别用默认图标

> 💡 名字和头像在发布后可以改，但改完要重新发版审核，尽量一次定好。

**验证**：应用创建成功，能进入应用详情页看到「凭证与基础信息」。

---

### 步骤二：七鱼侧绑定应用

**在哪做**：七鱼后台 → `在线客服 → 在线接入 → 飞书接入 → IM 消息` → 【绑定飞书应用】

**填什么** ✅

| 七鱼字段 | 来源 |
|---|---|
| App ID | 飞书应用 → 凭证与基础信息 → 应用凭证 |
| App Secret | 同上 |
| Encrypt Key | 飞书应用 → 事件与回调 → 加密策略 |
| Verification Token | 同上 |

填完点 **【保存】**。

**保存后会发生什么** ✅

系统自动生成一个 **回调请求地址**（Request URL）。**立刻复制下来**，下一步要用。

**验证**：页面上能看到生成的回调地址，形如 `https://...qiyukf.com/...`。

> ⚠️ 如果保存后没生成地址，通常是 App ID / App Secret 填错或有多余空格。先清空重填，别急着往下走。

---

### 步骤三：把回调地址回填飞书

**在哪做**：飞书应用 → **事件配置** 和 **回调配置**（两个页面都要填）

**怎么做** ✅

1. 把步骤二拿到的回调地址，填入「事件配置」的请求地址
2. 同样的地址填入「回调配置」的请求地址
3. 订阅方式选择 **【将回调发送至开发者服务器】**
4. 点 **【保存】**

**验证** ✅

- 飞书页面提示「配置成功」或「验证通过」
- 如果飞书侧提示验证失败，回七鱼确认应用信息是否填全（尤其是 Encrypt Key / Verification Token）

> ⚠️ 两个页面填的是**同一个地址**，别以为第二处要换个地址。

---

### 步骤四：加机器人 + 开权限 + 订阅事件

这一步是全流程最容易漏的地方，三件事都要做。

#### 4.1 添加机器人能力

**在哪做**：飞书应用 → 添加应用能力 → **机器人** → 添加

#### 4.2 开通权限

**在哪做**：飞书应用 → 权限管理 → 【开通权限】

按下面清单逐项勾选 ✅：

| 权限名（中文） | Scope | 用途 |
|---|---|---|
| 获取通讯录基本信息 | `contact:contact.base:readonly` | 员工信息变化事件 |
| 获取用户基本信息 | `contact:user.base:readonly` | 识别访客身份 |
| 获取用户 user ID | `contact:user.employee_id:readonly` | 身份认证 |
| 获取与更新群组信息 | `im:chat` | 群配置修改事件 |
| 获取与发送单聊、群组消息 | `im:message` | **收发消息（核心）** |
| 接收群聊中@机器人消息事件 | `im:message.group_at_msg:readonly` | 群里 @ 进线 |
| 读取用户发给机器人的单聊消息 | `im:message.p2p_msg:readonly` | 单聊进线 |
| 获取与上传图片或文件资源 | `im:resource` | 图片/附件收发 |
| 获取群组中用户和机器人发送的消息 | `im:message.group_msg.include_bot:read` | 群内全量消息 |

> ⚠️ 最后一项（`im:message.group_msg.include_bot:read`）是**敏感权限**，飞书可能要求管理员额外审批，提前跟飞书管理员打招呼。

#### 4.3 订阅事件

**在哪做**：飞书应用 → 事件配置 → 添加事件

必须订阅这四类 ✅：

| 事件 | 依赖权限 |
|---|---|
| **接收消息** | 接收群聊中@机器人消息事件、读取用户发给机器人的单聊消息、获取群组中所有消息（敏感）、获取群组中其他机器人和用户@当前机器人的消息、获取群组中用户和机器人发送的消息 |
| **消息撤回** | 获取与发送单聊、群组消息 |
| **群配置修改** | 获取与更新群组信息 |
| **员工信息变化** | 获取通讯录基本信息 |

**验证**：事件列表里能看到这四项，状态正常。

---

### 步骤五：创建版本并发布

**在哪做**：飞书应用 → 版本管理与发布 → 【创建版本】

**怎么做** ✅

1. 版本号填 **1.0.0**
2. 可用范围按需求选，**无特殊情况建议「所有员工」**
3. 填写更新说明
4. 保存 → 点 **【申请线上发布】**

**然后等飞书管理员审核** ✅

飞书管理员在 `飞书管理后台 → 工作台 → 应用审核` 页面通过上线申请。

**验证**：应用状态变为「已发布 / 已上线」，在飞书工作台能搜到。

> ⚠️ **权限或事件改完必须重新发版。** 飞书的权限和事件是在「版本」里生效的，改完不创建新版本、不重新审核，等于没改。这一步最容易漏，也最容易让人误以为「配置不生效」。

---

### 步骤六：配置会话接入条件

**在哪做**：七鱼后台 → 飞书 IM 消息渠道配置 → 会话接入条件

**两个选项** ✅

| 选项 | 行为 | 什么时候用 |
|---|---|---|
| **全部消息接入** | 群里每一条消息都生成/延续会话 | 群很安静、每句话都是业务咨询 |
| **被 @ 后接入**（推荐） | 客户 @ 机器人后进线，该群里后续消息不用再 @ | 绝大多数客户群 |

> ⚠️ 选「全部消息接入」在活跃群里会产生大量噪声会话，客服工作量统计、质检抽样、会话量报表全部失真。**默认选「被 @ 后接入」。**

**验证**：配置保存后，去测试群 @ 一下机器人，看七鱼工作台是否弹出会话。

## 4. 权限与事件完整清单

### 4.1 权限速查（复制给飞书管理员）

```
contact:contact.base:readonly
contact:user.base:readonly
contact:user.employee_id:readonly
im:chat
im:message
im:message.group_at_msg:readonly
im:message.p2p_msg:readonly
im:resource
im:message.group_msg.include_bot:read
```

### 4.2 权限 → 能力映射

| 缺哪项会怎样 | 缺失的权限 |
|---|---|
| 消息完全收发不了 | `im:message` |
| 群里 @ 机器人没反应 | `im:message.group_at_msg:readonly` |
| 单聊进不来 | `im:message.p2p_msg:readonly` |
| 群里非 @ 的消息看不到 | `im:message.group_msg.include_bot:read` |
| 图片、文件收发失败 | `im:resource` |
| 群名/群成员变化不同步 | `im:chat` |
| 访客身份识别不出来、员工信息不同步 | 三个 `contact:*` 权限 |

## 5. 群聊场景配置细节

### 5.1 把机器人拉进群

**怎么做** ⚠️

1. 在飞书群里 → 群设置 → 群机器人 → 添加机器人
2. 搜索步骤一创建的应用名
3. 添加后，群里会有一条「XX 已加入群聊」的系统消息

> ⚠️ 机器人加入后**不会自动打招呼**。想让它发欢迎语，得在七鱼侧配欢迎语，或让客户先 @ 一次触发会话。

### 5.2 「客户群」到底是什么群

飞书的群分三种，只有前两种能用：

| 群类型 | 说明 | 能否用 |
|---|---|---|
| **企业内部群** | 全部是本企业成员 | ✅ 可以（适合内部服务台场景） |
| **外部群**（自己建，拉客户进来） | 群主是本企业，成员含外部联系人 | ✅ 可以，**这是「客户群」的典型形态** |
| **外部群**（客户建，拉你进去） | 群主是别的飞书企业 | ❌ 走不通，见 [8.1](#81-跨租户限制) |

### 5.3 群会话的分配

群聊进线后，分配逻辑和普通在线会话一致，走的是同一套规则：

```
VIP进线规则 > 会话邀请 > 机器人转人工 > 代码/链接指定 > 高级分配 > 基础分配
```

想让客户群固定分给某几个人，用 `高级分配 → 自定义规则`，流转形式选「**指定**」，把这几个人从默认分流组移除。⚠️

### 5.4 群内多客服

一个群可以多个客服轮流接待，会话会显示当前接待人。⚠️ 但同一时刻只有一个人持有会话，转交要显式操作。

## 6. 分阶段验收清单

别一次全测，按层验证，出问题时定位快得多。

### 阶段一：应用层（飞书侧）

- [ ] 应用已发布，状态「已上线」
- [ ] 飞书工作台能搜到应用
- [ ] 应用详情里 9 项权限全部「已开通」
- [ ] 事件配置里 4 类事件全部订阅
- [ ] 事件配置的请求地址 = 七鱼生成的回调地址

### 阶段二：通道层（消息通不通）

- [ ] 把机器人拉进测试群，成功
- [ ] 群里 @ 机器人发「测试」，七鱼工作台**弹出会话**
- [ ] 客服在七鱼回复，消息**回到群里**，显示为机器人发送
- [ ] 再发一条不带 @ 的消息，确认是否进线（验证「被 @ 后接入」是否生效）

### 阶段三：会话层（业务对不对）

- [ ] 客户身份能识别（工作台能看到客户名称/ID，而不是「访客12345」）
- [ ] 图片能收发
- [ ] 文件能收发
- [ ] 会话能正常结束
- [ ] 满意度评价能发出（如果开了）

### 阶段四：数据层（能不能用起来）

- [ ] 会话能在「会话记录」里查到
- [ ] 会话归属的渠道显示为「飞书」
- [ ] 质检导出能覆盖到这个会话（见 [第 9 节](#9-与聊天记录导出链路的关系)）

## 7. 故障排查对照表

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 七鱼保存后**没生成回调地址** | App ID / Secret 填错或有空格 | 清空重填，确认从飞书页面完整复制 |
| 飞书保存回调地址**提示验证失败** | Encrypt Key / Verification Token 没填或填错 | 回七鱼检查这两项；确认两边是同一个应用 |
| 群里 @ 机器人**没反应** | ① 缺 `im:message.group_at_msg:readonly` ② 事件没订阅「接收消息」③ 权限改了没重新发版 | 按顺序查这三项，第三项最常见 |
| 消息能进七鱼，**客服回复发不出去** | 缺 `im:message`，或应用没加「机器人」能力 | 补权限 + 加机器人能力 + 重新发版 |
| 客户身份显示为「访客XXXX」 | 缺 `contact:user.base:readonly`；或该客户是外部租户用户，user_id 取不到 | 补权限；外部租户情况见 [8.2](#82-客户身份识别打折) |
| 群里**非 @ 的消息不进线** | 接入条件选了「被 @ 后接入」 | 这是正常行为，改选「全部消息接入」才会全进 |
| 同一句话**生成多条会话** | 旧版本 bug | 2026-09 版本已修复（消息 id 相同时不再重复创建），升级即可 |
| 图片/文件发不出去 | 缺 `im:resource` | 补权限 + 重新发版 |
| 群里有人退群/群名改了，七鱼没同步 | 缺 `im:chat` 或没订阅「群配置修改」 | 补权限 + 订阅事件 + 重新发版 |
| **改了权限但一直不生效** | 没创建新版本 / 没重新审核上线 | 版本管理 → 创建版本 → 申请发布 → 管理员审核 |

## 8. 已知限制与能力边界

### 8.1 跨租户限制

**这是最容易被忽略、也最致命的限制。** ⚠️

飞书「企业自建应用」的可用范围**只覆盖本企业成员**。

| 场景 | 结果 |
|---|---|
| 你建的群，把客户（外部联系人）拉进来 | ✅ 能用 |
| 客户在自己飞书企业里建群，把你拉进去 | ❌ 走不通 |

原因：机器人是你这个租户的应用，跨不到对方租户。要跨租户得做成「对外共享应用」，那是另一套流程，七鱼这条接入线按官方文档是走自建应用。

**结论**：想用这个渠道，**群必须由你方创建**，客户作为外部联系人被邀请进来。

### 8.2 客户身份识别打折

七鱼识别客户靠飞书 user_id。外部联系人的 user_id **未必拿得到**。⚠️

后果：

- 同一个客户在不同群里，可能被当成不同访客
- 客户标签、历史会话、客户档案对不上
- 想做客户画像、复购分析，数据会断

**应对**：如果客户画像重要，在中转层自己做映射（例如群 ID + 客户手机号 → 内部客户 ID），或者要求客户先在你方系统注册再拉群。

### 8.3 消息类型支持矩阵

按官方版本更新公告（截至 2026-09）✅：

| 消息类型 | 支持情况 |
|---|---|
| 文本 | ✅ |
| 图片 | ✅ |
| 文件 | ✅ |
| 富文本 | ✅（单聊遇到不支持类型时展示兜底提示「暂不支持此消息类型」） |
| 引用消息 | ✅（被引用的图片、视频、文件同样支持展示） |
| 表情（emoji） | ✅ 按引用消息格式展示；多个表情展示为多条；**未适配的 emoji 直接展示中文**；该格式**不支持客服引用回复** |
| 位置 | ✅ 展示位置名称 |
| 视频通话 | ✅ 展示标题与开始时间 |
| 语音 | ⚠️ 未见明确说明，建议实测 |

### 8.4 其它限制

- **客服引用回复**：普通消息可以引用访客消息和客服消息并回传飞书 ✅；但表情引用格式的消息不支持引用回复 ✅
- **群操作**：飞书群的操作列表里有【发起会话】按钮，可按历史会话发起新会话 ✅（2026-07 新增）

## 9. 与聊天记录导出链路的关系

飞书群聊产生的会话，**和网页、App、微信渠道的会话一样落库**，会被下面两个接口覆盖：

| 接口 | 拿到什么 | 跨度限制 |
|---|---|---|
| `POST /openapi/export/session` | 会话元数据（60+ 字段，**无逐句正文**） | ≤ 5 天 |
| `POST /openapi/chat/inspect/result/download` | 含「会话内容」的 xlsx（**唯一能拿正文的**） | ≤ 2 天 |

> ⚠️ 质检导出**只包含被质检任务扫过的会话**。飞书渠道的会话是否纳入质检，取决于质检任务的范围配置 —— 如果发现导出的正文里没有飞书会话，先去质检任务里确认渠道范围。

字段对应关系（`fromType` 字段）：

```
Web / Wx / wx_ma / App / Ios / Android / Open / 飞书渠道
```

具体取值以实际返回为准，可在 `export/session` 返回里按 `fromType` 筛。

### 10.2 版本能力演进

| 时间 | 变化 |
|---|---|
| 2025-07 | 新增「飞书群聊」渠道，**专业版及以上**，支持对客群聊接待 ✅ |
| 2026-01 | 飞书 IM 消息新增**单聊**接入（企业内部人员单聊 + 对客单聊）；明确「延续飞书 IM 渠道现有接入方式，无需额外新增一套独立渠道配置」✅ |
| 2026-07 | 支持引用消息与富文本消息；飞书群操作列表新增【发起会话】按钮 ✅ |
| 2026-09 | 支持接收表情、位置、视频通话消息；修复同一访客消息重复生成多条会话 ✅ |

> ❓ **关于「飞书群聊」是否是一个独立渠道入口**
> 2025-07 公告说「新增渠道：飞书群聊」，2026-01 公告又说单聊「延续现有接入方式，无需新增独立渠道配置」。
> 两句话的合理理解是：**群聊和单聊都是「飞书 IM 消息」渠道下的能力**，统一配置在 `在线接入 → 飞书接入 → IM 消息`。
> 但如果你的后台在 `在线接入` 下能看到单独的「飞书群聊」渠道项，就按同样的六步配置，只是入口换一个位置。以实际后台为准。
